# WanGP Studio 1.4.0 — Unified Media & Workflow Experience

Date: 2026-11-05
Status: planned (approved direction from the 1.3.4 control audit)
Baseline: 1.3.5 (`a4188789`), all suites green, e2e harness in place

## Goal

Make Gallery, Workflow and Generate one working environment instead of three
separate tools. The flagship scenario for the cycle:

**Media → Workflow → Generate → Result** — pick a media item, drop it into a
workflow node as input, run through the native WanGP queue, and see the result
linked back to the workflow run in the Gallery.

Constraints carried over from Roadmap v3: one WanGP runtime, one native
queue, one MMGP allocator, no second backend, no WanGP core changes.

## Backlog carried from the 1.3.4 control audit

Closed in 1.3.5 (`a4188789`): bounded upload history + File release,
generation-scoped fetch tokens, empty-uploads-panel visibility regression,
honest deep-scroll content check, manual/weekly media benchmark workflow.

Deferred to this cycle: live-browser verification of the SendTo click→popup

## P1 items

### 1. Media → Workflow

Gallery lightbox gets "Use in workflow": pick target node type (input image /
input video / reference) and the workflow canvas receives the file. Check
first what WanFlow UI already provides (the Compare A/B node, Input Image
node and the resource preflight are local-fork features) so we extend the
existing node plumbing instead of adding a parallel path.

Acceptance: e2e — select a media item, land it as an Input Image node
parameter, run a two-node graph, see the output file in the Gallery.

### 2. Workflow → Gallery

Workflow runs already write into the media roots; the missing piece is the
link. Record `workflow_run_id` (and node title) in the output sidecar so the
Gallery lightbox can show "produced by run X" with a jump back to the run.

Acceptance: run a graph, open the produced file's lightbox, see the run
reference.

### 3. Generation History

The native WanGP queue already keeps settings per task; Studio keeps job
history (50 entries, `test_jobs_sse.py`). Add "Repeat with same settings" on
a finished job: resubmit the stored settings payload through the existing
POST /api/jobs path.

Acceptance: e2e/API — submit, finish (or mock completion), repeat, verify the
new job carries identical settings.

## P2 items

### 4. Workflow templates

Preset I2V/T2V graphs as one-click templates. The WanFlow fork already ships
example graphs (`examples/*.json`) — reuse that format; templates are
graph-store entries flagged `template: true`.

### 5. Upload UX in Workflow

Drag & drop onto the canvas creates an Input node with the file; reuses the
Upload Center queue server-side.

### 6. Queue UX

The Studio tasks panel links job → workflow run → produced media items
(needs item 2's sidecar link).

## P3

### 7. Plugin Health history

Append-only local log (workspace JSON) of update/rollback events detected by
Plugin Health scans; shown in the Plugins view.

## Test strategy

- Every frontend change ships an e2e test in the existing Playwright harness.
- Backend changes extend the studio TestClient suite.
- The vendored WanFlow diff must stay reconciled: `test_vendored_sync.py`
  gates every commit.
- Strict GPU acceptance before closing the cycle:
  `WANFLOW_REQUIRE_CUDA=1 WANFLOW_UI_REQUIRED=1` full local run.
