# Спецификация: H3 Scene Studio v2.1 — библиотека сцен, цепочки, быстрый рецепт

Дата: 2026-10-07 · Статус: утверждено на дизайн-ревью · Плагин: `plugins/h3-scene-studio/`

## 1. Цель и контекст

H3 Scene Studio — вкладка WanGP для сборки сцен MiniMax H3 Ref2VA (референс-фото,
рандомизированные таймированные акты, камера/звук → английский промпт + фото в генератор).
Сегодня: настройки сцены не сохраняются между сессиями; одна кнопка «Вставить в генератор»
пишет только промпт и фото; мульти-сценовые истории собираются вручную.

V2.1 добавляет три связанных возможности (подтверждено пользователем):

1. **Библиотека сцен** — сохранение/загрузка полного снимка настроек сцены.
2. **Сюжетные цепочки** («сцена = клип») — N сцен → N задач в живой очереди WebUI одним действием.
3. **Быстрый рецепт генерации** — измеренные бенчмарком настройки применяются при вставке
   и вшиваются в задачи цепочки.

Вне скоупа (YAGNI, по решению дизайн-ревью): сохранение цепочек как файлов,
поредакторное редактирование кадра цепочки, автосвязки промптов между кадрами.

## 2. Исследовательская база

- Механизм постановки в очередь: `api_session.submit_manifest([{settings}, ...])`
  (`shared/api.py:829`), доступный уже сейчас — конструктор вкладки получает
  `api_session` (`plugin.py:301`, инжект в `shared/utils/plugins.py:1740-1752`).
  Задачи проходят штатную `validate_task` и попадают в живую очередь WebUI
  (`shared/api_webui.py:289-316` → `wgp.py:2151-2167`). Прецеденты: `plugins/sample`
  (`submit_task` с параметрами), `plugins/wan2gp-wanflow-ui` (графы через per-node submit).
- `image_refs` — реальное поле настроек задачи (`wgp.py:186/200/1123/1546`).
- Параметры задачи передаются в словаре settings; запись в UI-компоненты влияет
  только на следующую ручную генерацию пользователя.
- Отчёт: `docs/superpowers/research/2026-10-07-plugin-queue-integration.md`.
- Бенчмарк (RTX 5070 Ti Laptop 12GB): H3 832x480/124 кадра — 8 шагов 97 c,
  6 шагов 76 c (x1.28), 4 шага 60 c; выбран 6 шагов как баланс.

## 3. Feature 1 — Библиотека сцен

**Хранение.** `SCENES_DIR = plugins/h3-scene-studio/scenes/` (константа уже объявлена,
`plugin.py:35`, не используется). Одна сцена = один JSON:

```json
{
  "name": "кухня-утро",
  "created": "2026-10-07T12:00:00",
  "settings": { ...полный словарь collect() без files/picCountN... },
  "photo_set": "мария-казино",
  "prompt": "последний собранный промпт (справочно)"
}
```

**UI** — новый аккордеон «💾 Сцены» (между референсами и «Сцена и люди»):
кнопки «💾 Сохранить сцену», «📂 Загрузить», «🗑 Удалить»; дропдаун сохранённых сцен;
имя сцены — textbox (пусто → автогенерация `сцена-YYYYmmdd-HHMMSS`).

**Поведение.**
- Сохранение: снимок `collect()` от текущих компонентов + имя выбранного фото-набора
  (если в `sets_dd` выбран существующий набор) + текущий промпт.
- Загрузка: возвращает `gr.update` для всех компонентов; если `photo_set` существует,
  фото набора подгружаются в `gallery`/`files`; если нет — предупреждение в статус.
- Удаление: удаляет JSON, обновляет дропдаун.
- Имена сцен — файлобезопасные (санитизация `[\w\-\u0400-\u04FF ]` → `_`).

**Не трогается:** `PHOTOS_DIR`, существующие обработчики фото-наборов, `vocab.py`, `engine.py`.

## 4. Feature 2 — Сюжетные цепочки («сцена = клип»)

**Семантика (подтверждено):** сцена = одна генерация (клип); цепочка из N сцен =
N независимых задач в очереди с общими актёрами/местом. H3-нативная нарезка внутри
клипа не используется.

**UI** — аккордеон «📖 Цепочка»:
- «➕ Добавить текущую сцену» — снимает `collect()` в память цепочки (плюс текущий
  фото-набор и/или загруженные файлы).
- Список кадров: `gr.DataFrame` (колонки «№», «сцена», «сек», «фото») с кнопками
  «↑», «↓», «✖» (применяются к выбранному номеру строки).
- Дропдаун «Модель для цепочки»: варианты Ref2VA-файнтюнов из `finetunes/`
  (`minimax_h3_10eros_max_b5_ref2va` по умолчанию, `minimax_h3_ref2va_pruned` и др. —
  список хардкодом в плагине, не сканирование).
- «▶️ Отправить цепочку в очередь».

**Отправка.** Для каждой сцены цепочки:
1. `engine.build(scene_settings)` → свежий промпт (случайность движка — фича:
   каждая генерация даёт новый вариант).
2. `video_length` = кадры из «Секунд на кадр» сцены, приведённые к сетке H3:
   `x = max(5, round(sec * 24)); length = x + (5 - x % 17) % 17` (17k+5 при 24 fps,
   формула из ComfyUI-прецедента, math-нода workflow v2.5).
3. Рецепт (раздел 5) в параметры задачи.
4. `image_refs` = пути фото привязанного набора (до 4, `ref1..ref4`), либо
   текущие загруженные файлы, если сцена добавлена без набора.
5. `model_type` = выбранная модель цепочки; `seed` = -1.
6. Всё собирается в один `api_session.submit_manifest(tasks)`; результат —
   статус «В очередь добавлено N из M задач. Модель: …». Ошибка → `gr.Error`
   с текстом от API; очередь при частичном сбое не портится (manifest атомарен
   на стороне `load_queue_action`).

**Состояние цепочки живёт в памяти вкладки** (python-список в замыкании `create_tab`);
при перезагрузке страницы цепочка сбрасывается — осознанное упрощение v2.1.

## 5. Feature 3 — Быстрый рецепт генерации

Измеренные значения (бенчмарк `run-addendum`, H3): **832x480, 6 шагов**,
`video_length` по сетке 17k+5 из «Секунд на кадр».

- **Кнопка «➡️ Вставить в генератор»** — прежнее поведение (промпт + фото в форму,
  чтобы можно было отредактировать) плюс выставление компонентов основной формы
  `num_inference_steps=6`, `resolution="832x480"`, `video_length=<кадры>`.
  Реестр компонентов ключуется именами параметров `save_inputs`
  (`shared/utils/plugins.py:1625-1635` резолвит `request_component` по
  `generator_tab_components`), `resolution` подтверждён прецедентом
  `plugins/sample/plugin.py:31`; `num_inference_steps`/`video_length` — параметры
  `save_inputs` (wgp.py:1156, 12454), резолвятся аналогично; если какого-то
  ключа нет в реестре — пропустить и дописать в статус: «выставьте вручную:
  832x480, 6 шагов».
  Статусная строка всегда напоминает: «Модель: MiniMax H3 Ref2VA».
- **Задачи цепочек** — рецепт вшивается в словарь задачи напрямую
  (надёжнее, чем UI): `{"num_inference_steps": 6, "resolution": "832x480",
  "video_length": <17k+5>}`. Остальные параметры (solver, guidance, flow_shift)
  не переопределяются — наследуются от дефолтов файнтюна.

## 6. Архитектура изменений

Файлы:
- `plugins/h3-scene-studio/plugin.py` — основной объём: аккордеоны, обработчики,
  вызовы `submit_manifest`, `request_component` для рецепта (~150-200 строк).
- `plugins/h3-scene-studio/scene_store.py` — **новый модуль**: save/load/delete/list
  сцен (JSON, санитизация имён, миграции не нужны). Чистые функции, тестируемые
  без Gradio.
- `plugins/h3-scene-studio/engine.py` — без изменений (build получает словарь).
- `plugins/h3-scene-studio/vocab.py` — без изменений.

Обратная совместимость: все существующие кнопки работают как раньше; новые
элементы добавляются, ничего не удаляется. Версия в `plugin_info.json` → 2.1.0.

## 7. Обработка ошибок

- Пустой промпт при сохранении сцены — допустимо (промпт справочный).
- Цепочка из 0 сцен → `gr.Error("Цепочка пуста")`.
- Отсутствие фото и у сцены, и в форме → задача без `image_refs`
  (Ref2VA без референсов деградирует до T2VA — предупредить в статусе).
- `submit_manifest` недоступен (нет api_session) → `gr.Error` с явным текстом.
- Диск/IO при сохранении сцены → `gr.Error` c сообщением ОС.
